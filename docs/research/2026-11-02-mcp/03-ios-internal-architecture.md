# iOS/iPadOS host architecture for remote MCP Streamable HTTP

Research checked 2026-11-02. Scope: first-class iPhone/iPad host talking directly to remote Model Context Protocol (MCP) Streamable HTTP servers while retaining Askenly's existing local MLX inference (LFM3 and related models); reusable capabilities in `BraisenlyAI`; thin SwiftUI application/scene root in Askenly. No implementation, package/dependency selection, model weights, or device run performed. No weights were accessed or downloaded on largo.

## Decisions

1. **Use direct HTTPS Streamable HTTP from the app process.** Use `URLSession` for POST requests and consume response bytes/events incrementally. Keep request/task ownership in a reusable transport/service in `BraisenlyAI`; keep SwiftUI as presentation and scene-state wiring. Do not put network loops or MCP protocol state in `View.body`.
2. **Do not make iOS host launch stdio server processes.** The upstream Swift SDK's stdio transport reads/writes supplied POSIX file descriptors (stdin/stdout by default); its transport API is not a subprocess launcher. `Foundation.Process` is a macOS process API, not an iOS app facility. An SDK compiling with Darwin/POSIX pipe support proves descriptor transport support only, not permission or API support to launch a child server. Use remote HTTP for this app. Revisit only if an explicitly supported, signed, platform-permitted host process is specified.
3. **Keep persistent connection/auth state at app scope; keep chat presentation state per scene/conversation.** A SwiftUI app can have multiple scenes/windows, each with independent lifecycle. Do not create a duplicate MCP connection for every view/window by default; inject a shared connection/auth service from the app composition root and give each conversation/scene its own lightweight observable state. On scene background, checkpoint visible state and stop/close interactive streams; on foreground, reconnect and reconcile. Persist durable conversation data separately from in-memory stream/parser state.
4. **Treat a stream as foreground work.** An ordinary app soon suspends in background, cannot rely on continued CPU execution, and may be purged under memory pressure. Cancel or close interactive MCP stream tasks when the app backgrounds; persist partial output and request a fresh result/resume according to the negotiated server protocol when foregrounded. Do not use a background URL session for indefinite SSE; background sessions are intended for file upload/download and have different lifecycle semantics. Force-quit cancels background transfers and prevents automatic relaunch.
5. **Verify required local MLX and remote MCP coexistence on device.** “Remote” describes the MCP tool service; Askenly already runs local MLX inference (LFM3 and related models), and that remains in scope. MLX on Apple silicon uses unified physical memory shared by CPU and GPU; local weights and inference cache therefore compete with UI, network transport, and OS memory. Memory verification is mandatory on the lowest-memory supported iPhone and iPad, including cold model load, long generation while MCP streaming, background/foreground transitions, and memory pressure. Reduce/release model state where supported; no safe universal memory budget can be inferred from simulator or one device.
6. **OAuth is browser-mediated Authorization Code + PKCE with no localhost callback server.** Start the authorization URL in `ASWebAuthenticationSession`, receive the callback in its completion handler, validate state/issuer/audience as appropriate, and exchange the code using the PKCE verifier via `URLSession`. Use a registered app callback (custom scheme; on supported OS/provider setups, HTTPS callback/Universal Link). The user agent is controlled by AuthenticationServices; no loopback listener, embedded web view, client secret, or downloaded executable is needed. Keep token storage and refresh policy in reusable `BraisenlyAI` auth code, not the view. [RFC 8252: OAuth for Native Apps](https://datatracker.ietf.org/doc/html/rfc8252), [RFC 7636: PKCE](https://datatracker.ietf.org/doc/html/rfc7636).
7. **For `adagio.local`, declare local-network purpose and keep TLS identity valid.** Include `NSLocalNetworkUsageDescription` because direct unicast connections to local hosts are covered. `NSBonjourServices` is only needed if the app browses/registers/resolves a Bonjour service type; a configured host URL alone does not imply Bonjour service discovery. ATS documents special local-network handling for `.local`; keep `https://adagio.local:<configured-port>` and a certificate whose DNS name matches `adagio.local` and whose chain is trusted on the device. Do not rely on `.local` resolution, Local Network permission, or TLS trust succeeding on simulator as a substitute for a real Wi-Fi device check.

## Platform facts and availability

| Area | Evidence / version | Architecture consequence |
|---|---|---|
| `URLSession.AsyncBytes` | `bytes(for:)` / `bytes(from:)` and byte/line async sequences are available from iOS 15 (introduced in iOS 15 release notes); `AsyncBytes.task` exposes the underlying `URLSessionDataTask` for explicit cancellation. [Apple API](https://developer.apple.com/documentation/foundation/urlsession/bytes%28from%3Adelegate%3A%29), [iOS 15 release notes](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-15-release-notes) | Use async bytes for streaming, not `data(for:)` buffering the whole response. Retain/cancel the relevant task and propagate Swift task cancellation into it. Confirm selected deployment target before choosing API. |
| Network changes | `URLSessionConfiguration.waitsForConnectivity` makes URL loading wait for a viable path; Apple recommends attempting the request rather than stale preflight reachability checks. It does not promise an already-open long-lived stream survives Wi-Fi/VPN/path changes. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy?changes=_9%2C_9), [Apple networking Tech Talk](https://developer.apple.com/videos/play/tech-talks/111378/) | On stream failure/path change, surface waiting/retry state and reconnect with backoff; reconstruct the MCP client/session per server protocol. Test Wi-Fi loss/restore, VPN and switch to cellular. |
| App and scenes | Scene lifecycle is independent per scene; iOS may suspend a background app and disconnect a scene at any time. Background transitions should save state, quiet work, and free memory. [Managing app lifecycle](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle), [Preparing UI for background](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background) | App-shared auth/transport should not be owned by an ephemeral view. Conversation state must be restorable if a scene disconnects or the process is killed. |
| Background URLSession | Background configuration supports deferrable file upload/download when the app is suspended or system-terminated; it is not a general background execution lease. A user force-quit cancels transfers and prevents automatic relaunch. [Background configuration](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background%28withidentifier%3A), [background download guide](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background) | Keep MCP request/response streams foreground-bound. Do not assume background session can preserve a bidirectional/interactive MCP stream. |
| Memory pressure | iOS shares finite memory across apps/OS and can terminate apps under pressure; suspension memory and termination metrics exist. [Reduce terminations](https://developer.apple.com/documentation/xcode/reduce-terminations-in-your-app), [memory use](https://developer.apple.com/documentation/xcode/reducing-your-app-s-memory-use) | Release transient SSE/parser buffers, decoded tool results and optional model state when possible. Restore from persisted data rather than depending on process survival. |
| MLX | Apple’s WWDC25 MLX overview describes unified memory as CPU/GPU sharing physical memory. [WWDC25: Get started with MLX](https://developer.apple.com/videos/play/wwdc2025/315/) | Local inference can materially increase jetsam risk alongside chat UI; there is no free separate GPU memory pool. Keep out of default remote-chat path until device measurements justify it. |
| `ASWebAuthenticationSession` | Session API documented for iOS 12+; current typed `Callback` and HTTPS callback API are iOS/iPadOS 17.4+ (custom-scheme older initializer remains available but is deprecated in current docs). [Apple API](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession), [Callback API](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession/callback/customscheme%28_%3A%29) | If deployment target <17.4, keep compatibility path using `callbackURLScheme`; on 17.4+ choose HTTPS callback only when provider, associated domains, and redirect registration support it. The session owns callback delivery; no local port listener. |
| Local network | `NSLocalNetworkUsageDescription` is applicable to direct unicast local-host access. `NSBonjourServices` is for Bonjour service browsing/register/resolve. If local network access is first requested in background while permission is undetermined, iOS denies without showing the prompt. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy?changes=_9%2C_9), [Info.plist key](https://developer.apple.com/documentation/BundleResources/Information-Property-List/NSLocalNetworkUsageDescription) | Trigger first local-host connect in a user-visible foreground flow so permission can be explained and requested in context. No Bonjour list required unless service discovery is actually added. |
| ATS / `.local` / TLS | Apple documents `.local` specially under App Transport Security; local networking may require `NSAllowsLocalNetworking` for older OS compatibility / declared intent. URLSession still performs server trust evaluation; certificate name must match DNS name and anchor must be trusted. [ATS local setting](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking), [preventing insecure connections](https://developer.apple.com/documentation/security/preventing-insecure-network-connections), [local TLS](https://developer.apple.com/documentation/network/creating-an-identity-for-local-network-tls) | Confirm device trust chain and SAN for `adagio.local`; do not equate ATS’s `.local` exemption with HTTP being a good design or with self-signed cert auto-trust. No broad arbitrary-load exception. |
| Executable code | App Review 2.5.2 says iOS apps should be self-contained and may not download/install/execute code that changes app features/functionality. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/#software-requirements) | A remote MCP server is a network service, not code launched by the host. Stdio SDK support does not establish an allowed iOS subprocess architecture. |

## MCP transport/version caveat

The official MCP Swift SDK source inspected on 2026-11-02 provides `HTTPClientTransport` built around `URLSession.bytes(for:)`, JSON POST and SSE parsing, and `StdioTransport` built around supplied file descriptors. The checked SDK implementation identifies protocol version `2025-11-25`. Meanwhile, the official MCP repository’s current `2026-07-28` Streamable HTTP revision removes the standalone GET stream and protocol-level sessions and changes cancellation semantics. [Current MCP spec](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/streamable-http.mdx), [2025-11-25 transport](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/basic/transports.mdx), [SDK HTTP transport](https://github.com/modelcontextprotocol/swift-sdk/blob/main/Sources/MCP/Base/Transports/HTTPClientTransport.swift), [SDK stdio transport](https://github.com/modelcontextprotocol/swift-sdk/blob/main/Sources/MCP/Base/Transports/StdioTransport.swift).

**Do not choose an SDK/client implementation until the target MCP servers’ supported protocol versions are known.** Either pin a compatible protocol/SDK version or verify that the implementation negotiates/falls back correctly. This is a substantive compatibility point, not merely a transport name. The SDK's compilation checks and examples cannot prove interoperability with the actual server.

## Suggested component boundary

- `BraisenlyAI`: public reusable abstractions for MCP connection/configuration, Streamable HTTP transport, auth/PKCE/token storage, request cancellation/retry, and conversation/agent coordination as required. Keep Foundation-only or minimal platform imports in transport/auth so another host app can reuse them. Avoid app-specific `adagio.local` constants; inject server endpoint/configuration.
- Askenly app root: constructs shared dependencies and owns app-level coordination. Each SwiftUI `WindowGroup`/scene gets scene-specific chat presentation state, while authentication and (where server semantics permit) the remote connection are shared. `ContentView` renders and forwards user actions.
- No separate helper daemon or loopback callback server; preserve the existing local MLX inference path and its model delivery/storage arrangement.

## Unknowns to resolve before implementation

- Actual Askenly deployment target and minimum physical device. They determine availability gates, performance targets, and memory behavior.
- Actual remote MCP servers’ protocol-version support and authentication requirements, including whether server-initiated messages/features are needed.
- Whether local `adagio.local` is used by a shipped build or development only; certificate issuer/root installation path and mDNS availability on target Wi-Fi networks.
- OAuth authorization/token endpoints, registered redirect URI support, refresh/revocation behavior, and whether provider allows native public clients with PKCE.
- Exact existing local model variants, minimum supported device/iOS version, and measured memory headroom during concurrent local inference and MCP streaming; device verification remains mandatory.
- Real-device behavior for long-running URLSession streams across Wi-Fi/cellular/VPN changes, Local Network privacy prompt timing, TLS trust, background suspension, force quit, and multiwindow ownership remains unverified.
